## � 1. INTRODUCTION: When "It Works" Isn't Good Enough

### The Silent Environment Failure

**Thursday, 3 PM:**

```bash
Alice: $ python run_tests.py
All tests passed! ✅

Alice: $ git push
[CI pipeline runs on remote server]

CI: ❌ FAILED - ModuleNotFoundError: No module named 'requests'
```

**What happened?**

Alice has `requests` installed globally on her machine. CI has a fresh environment. The test suite never verified that dependencies were properly documented or isolated.

**Cost:** 30 minutes of CI time wasted, broken main branch, blocked teammates.

### What is a Smoke Test?

A **smoke test** is a basic validation that your system's core functionality works. The name comes from hardware testing: "Plug it in and make sure it doesn't start smoking."

**In software:**

- ✅ Does the environment have the right tools?
- ✅ Are they the correct versions?
- ✅ Can they communicate with each other?
- ✅ Is the configuration valid?

**Smoke tests are NOT:**

- ❌ Comprehensive feature testing
- ❌ Performance benchmarking
- ❌ Security audits

**Mental Model:** Smoke tests are like checking your car before a road trip:

- Gas in tank? ✅
- Tires inflated? ✅
- Engine starts? ✅
- Ready to drive cross-country? Maybe, but at least you won't break down in the driveway.

### Why This Tutorial Matters

You'll learn to:

1. **Write automated verification scripts** that detect problems before they become bugs
2. **Understand WSL2's architecture** at the system-call level
3. **Apply testing philosophy** to infrastructure, not just code
4. **Build CI/CD foundations** that scale to production systems

**The Philosophy:**

> "Testing doesn't start after you write code. It starts with verifying you can write code at all."

Let's build this incrementally. **Type along with me—don't just read.**

### 2.1 The Simplest Possible Check

Open your terminal in WSL2 and navigate to your project:

```bash
cd ~/pdm-system
```

Let's verify Python exists:

```bash
python3 --version
```

**Output:**

```
Python 3.12.3
```

**What just happened?**

1. Your shell (bash) parsed the command `python3 --version`
2. It searched your `$PATH` for an executable named `python3`
3. It found `/usr/bin/python3`
4. The kernel loaded and executed this program
5. Python printed its version to stdout
6. The shell displayed it in your terminal

**Key concept:** This is a **manual smoke test**. But what if you have 10 tools to check? 100? We need automation.

### 2.2 Building a Basic Checker Script

Create a new file:

```bash
nano check_python.sh
```

Type this exactly:

```bash
#!/bin/bash
# check_python.sh - Verify Python installation

echo "Checking Python..."
python3 --version
```

**Line-by-line explanation:**

- `#!/bin/bash`: **Shebang line**—tells the OS to execute this file with bash
- `# check_python.sh`: **Comment**—ignored by bash, documents the script
- `echo "Checking Python..."`: **Output message**—helps user understand what's happening
- `python3 --version`: **The actual check**—runs Python, shows version

Save (Ctrl+O, Enter, Ctrl+X) and make it executable:

```bash
chmod +x check_python.sh
```

**What does `chmod +x` do?**

It modifies the file's **permission bits** to mark it as executable:

```bash
ls -l check_python.sh
```

**Before `chmod +x`:**

```
-rw-r--r-- 1 alice alice 89 Oct 25 15:30 check_python.sh
```

**After `chmod +x`:**

```
-rwxr-xr-x 1 alice alice 89 Oct 25 15:30 check_python.sh
```

The `x` means "executable." Now the kernel knows this file can be run as a program.

Run it:

```bash
./check_python.sh
```

**Output:**

```
Checking Python...
Python 3.12.3
```

**� You just wrote your first automated check!**

But this script has a problem. Let's discover it together.

### 2.3 Understanding Exit Codes

Modify the script to check for a program that doesn't exist:

```bash
nano check_python.sh
```

Add a line:

```bash
#!/bin/bash
# check_python.sh - Verify Python installation

echo "Checking Python..."
python3 --version

echo "Checking fake program..."
fakeprogramthatdoesntexist --version
```

Save and run:

```bash
./check_python.sh
```

**Output:**

```
Checking Python...
Python 3.12.3
Checking fake program...
bash: fakeprogramthatdoesntexist: command not found
```

The script prints an error but **continues running**. Now check the **exit code**:

```bash
echo $?
```

**Output:**

```
127
```

**What's an exit code?**

Every program returns a number when it finishes:

- `0`: Success
- `Non-zero`: Failure (different numbers mean different errors)

The variable `$?` holds the exit code of the last command.

**Why this matters:**

Automated systems (CI/CD, monitoring tools) use exit codes to determine success/failure. A script that prints errors but returns `0` will fool them into thinking everything's fine.

### 2.4 Making the Script Fail Properly

Let's fix our script with proper error handling:

```bash
nano check_python.sh
```

Replace contents with:

```bash
#!/bin/bash
# check_python.sh - Verify Python installation with proper error handling

set -e  # Exit immediately if any command fails

echo "Checking Python..."
python3 --version

echo "Checking fake program..."
fakeprogramthatdoesntexist --version

echo "This line will never run if above fails"
```

Save and run:

```bash
./check_python.sh
echo "Exit code: $?"
```

**Output:**

```
Checking Python...
Python 3.12.3
Checking fake program...
bash: fakeprogramthatdoesntexist: command not found
Exit code: 127
```

**Notice:** The last `echo` inside the script never ran! The script exited as soon as a command failed.

**`set -e` explained:**

This is a bash directive that changes error-handling behavior:

- **Without `set -e`**: Commands fail, but script continues
- **With `set -e`**: First failure stops the entire script

**Best practice:** Always use `set -e` in automation scripts. Fail fast, fail loud.

### 3.3 Collecting All Results

Let's rewrite to collect all failures:

```bash
nano check_env_v2.sh
```

```bash
#!/bin/bash
# check_env_v2.sh - Check all tools and report all failures

# Don't use set -e here - we want to check everything

echo "=== Environment Smoke Test ==="
echo ""

FAILURES=0

# Check Python
echo -n "Checking Python... "
if python3 --version &>/dev/null; then
    echo "✅ $(python3 --version)"
else
    echo "❌ NOT FOUND"
    FAILURES=$((FAILURES + 1))
fi

# Check Node
echo -n "Checking Node.js... "
if node --version &>/dev/null; then
    echo "✅ $(node --version)"
else
    echo "❌ NOT FOUND"
    FAILURES=$((FAILURES + 1))
fi

# Check pnpm
echo -n "Checking pnpm... "
if pnpm --version &>/dev/null; then
    echo "✅ $(pnpm --version)"
else
    echo "❌ NOT FOUND"
    FAILURES=$((FAILURES + 1))
fi

# Check Git
echo -n "Checking Git... "
if git --version &>/dev/null; then
    echo "✅ $(git --version)"
else
    echo "❌ NOT FOUND"
    FAILURES=$((FAILURES + 1))
fi

echo ""
if [ $FAILURES -eq 0 ]; then
    echo "✅ All checks passed!"
    exit 0
else
    echo "❌ $FAILURES check(s) failed"
    exit 1
fi
```

**Let's understand this line by line:**

```bash
FAILURES=0
```

- Initialize a counter to track failures

```bash
echo -n "Checking Python... "
```

- `echo -n`: Print without newline (so result appears on same line)

```bash
if python3 --version &>/dev/null; then
```

- `if command; then`: Run command, check if it succeeded (exit code 0)
- `&>/dev/null`: Redirect all output to `/dev/null` (discard it)
- **Why?** We don't want the version output during the check, only in our formatted output

```bash
    echo "✅ $(python3 --version)"
```

- `$(command)`: **Command substitution**—runs command, inserts its output here
- This is how we get the version string to display

```bash
else
    echo "❌ NOT FOUND"
    FAILURES=$((FAILURES + 1))
```

- `$((expression))`: **Arithmetic expansion**—evaluates math
- Increment failure counter

```bash
if [ $FAILURES -eq 0 ]; then
```

- `[ expression ]`: Test condition
- `-eq`: Numeric equality test


```bash
#!/bin/bash
set -euo pipefail  # "Strict mode"
```

**What each does:**

```bash
# -e: Exit on error
command_that_fails
echo "Never runs"

# -u: Exit on undefined variable
echo $UNDEFINED_VARIABLE  # Exits with error
```

```bash
# -o pipefail: Catches failures in pipes
false | true  # Without pipefail: succeeds (true exit code)
              # With pipefail: fails (false exit code)
```

Create this experiment:

**How `$(command)` works:**

2. Creates a **subshell** (child process)
3. Runs command in subshell
4. Captures stdout
5. Substitutes the output into the string

**Subshell visualization:**

```
Parent shell (your script)
    ├─ Forks child process
    │   └─ Runs: python3 --version
    │   └─ Outputs: Python 3.12.3
    ├─ Captures output
    └─ Inserts: "Python 3.12.3"
```

## � 6. BUILDING A PRODUCTION-GRADE CHECKER

Now let's combine everything we've learned into a professional smoke test.

### 6.1 The Final Script

Create the ultimate environment checker:

```bash
nano check_environment.sh
```

```bash
#!/bin/bash
# check_environment.sh - Production-grade environment smoke test

set -euo pipefail  # Strict mode

# Colors for output
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
NC='\033[0m' # No Color

# Counters
TOTAL_CHECKS=0
PASSED_CHECKS=0
FAILED_CHECKS=0

# Helper function to check command existence
check_command() {
    local cmd=$1
    local expected_version=$2

    TOTAL_CHECKS=$((TOTAL_CHECKS + 1))

    echo -n "Checking $cmd... "

    if command -v "$cmd" &>/dev/null; then
        local version=$($cmd --version 2>&1 | head -n 1)

        if [ -n "$expected_version" ]; then
            # Version checking logic could be enhanced
            echo -e "${GREEN}✅${NC} $version"
        else
            echo -e "${GREEN}✅${NC} $version"
        fi

        PASSED_CHECKS=$((PASSED_CHECKS + 1))
        return 0
    else
        echo -e "${RED}❌ NOT FOUND${NC}"
        FAILED_CHECKS=$((FAILED_CHECKS + 1))
        return 1
    fi
}

# Helper function to check WSL2
check_wsl2() {
    TOTAL_CHECKS=$((TOTAL_CHECKS + 1))

    echo -n "Checking WSL2 kernel... "

    if uname -r | grep -q "microsoft"; then
        local kernel=$(uname -r)
        echo -e "${GREEN}✅${NC} $kernel"
        PASSED_CHECKS=$((PASSED_CHECKS + 1))
        return 0
    else
        echo -e "${YELLOW}⚠️${NC}  Not in WSL2 (native Linux?)"
        PASSED_CHECKS=$((PASSED_CHECKS + 1))
        return 0
    fi
}

# Helper function to check Git config
check_git_config() {
    TOTAL_CHECKS=$((TOTAL_CHECKS + 1))

    echo -n "Checking Git configuration... "

    local git_name=$(git config user.name 2>/dev/null)
    local git_email=$(git config user.email 2>/dev/null)

    if [ -n "$git_name" ] && [ -n "$git_email" ]; then
        echo -e "${GREEN}✅${NC} $git_name <$git_email>"
        PASSED_CHECKS=$((PASSED_CHECKS + 1))
        return 0
    else
        echo -e "${RED}❌ NOT CONFIGURED${NC}"
        echo "  Run: git config --global user.name \"Your Name\""
        echo "  Run: git config --global user.email \"you@example.com\""
        FAILED_CHECKS=$((FAILED_CHECKS + 1))
        return 1
    fi
}

# Helper function to check directory
check_directory() {
    TOTAL_CHECKS=$((TOTAL_CHECKS + 1))

    echo -n "Checking project directory... "

    if [ -d ".git" ]; then
        local repo_path=$(pwd)
        echo -e "${GREEN}✅${NC} $repo_path (Git repo)"
        PASSED_CHECKS=$((PASSED_CHECKS + 1))
        return 0
    else
        echo -e "${RED}❌ Not a Git repository${NC}"
        FAILED_CHECKS=$((FAILED_CHECKS + 1))
        return 1
    fi
}

# Main execution
echo "======================================"
echo "  Environment Smoke Test"
echo "======================================"
echo ""

echo "�️  System Information:"
check_wsl2
echo ""

echo "�️  Development Tools:"
check_command "python3" ""
check_command "node" ""
check_command "pnpm" ""
check_command "git" ""
echo ""

echo "� Configuration:"
check_git_config
check_directory
echo ""

echo "======================================"
echo "  Results"
echo "======================================"
echo "Total checks: $TOTAL_CHECKS"
echo -e "${GREEN}Passed: $PASSED_CHECKS${NC}"

if [ $FAILED_CHECKS -gt 0 ]; then
    echo -e "${RED}Failed: $FAILED_CHECKS${NC}"
    echo ""
    echo "❌ Environment check FAILED"
    exit 1
else
    echo -e "${RED}Failed: 0${NC}"
    echo ""
    echo "✅ Environment check PASSED"
    echo "Your development environment is ready!"
    exit 0
fi
```

### 6.2 Functions in Bash

```bash
check_command() {
    local cmd=$1
    # function body
}
```

**Breaking it down:**

- `function_name()`: Declares a function

```
  ESC   style  color
```

**Common codes:**

- `0;31m`: Red
- `0;32m`: Green
- `1;33m`: Bold yellow
- `0m`: Reset

## � 9. TESTING PHILOSOPHY: SMOKE TESTS IN THE TESTING PYRAMID

### 9.1 Understanding the Testing Pyramid

```
          /\
         /  \
        /E2E \    ← Few, slow, expensive
       /------\
      / Integr \  ← Some, moderate
     /----------\
    /   Unit     \ ← Many, fast, cheap
   /--------------\
  / Infrastructure \ ← Foundation (smoke tests live here)
 /------------------\
```

**Where smoke tests fit:**

- **Below** unit tests
- **Foundation** of the entire testing strategy
- **Pre-condition** for running anything else

**Why?**

If your environment is broken:

- Unit tests can't run
- Integration tests can't connect
- E2E tests can't start servers

**Analogy:** Smoke tests are like checking if the power is on before testing a lightbulb.

### 9.2 Smoke vs. Other Test Types

| Test Type       | Purpose                        | Speed     | When to Run       |
| --------------- | ------------------------------ | --------- | ----------------- |
| **Smoke**       | "Does system turn on?"         | Very fast | Before any work   |
| **Unit**        | "Does function work?"          | Fast      | After each change |
| **Integration** | "Do components work together?" | Moderate  | Before commit     |
| **E2E**         | "Does full system work?"       | Slow      | Before release    |

### 9.3 Fail Fast Philosophy

**Bad workflow:**

```
1. Write code for 2 hours
2. Try to run tests
3. Discover Python is wrong version
4. Install correct version
5. Discover missing dependencies
6. Install dependencies
7. Finally run tests
8. Tests fail due to code bugs (actual issues)
```

**Good workflow:**

```
1. Run smoke test (30 seconds)
2. Environment confirmed good
3. Write code for 2 hours
4. Run tests
5. Tests fail due to code bugs (expected)
6. Fix bugs, iterate
```

**Time saved:** 1-2 hours of debugging environment issues

```python
#!/usr/bin/env python3
"""
check_environment.py - Production-grade environment smoke test in Python
"""

import subprocess
import sys
import os
from pathlib import Path


class EnvironmentChecker:
    """Validates development environment setup."""

    def __init__(self):
        self.total_checks = 0
        self.passed_checks = 0
        self.failed_checks = 0

        # ANSI color codes
        self.GREEN = '\033[0;32m'
        self.RED = '\033[0;31m'
        self.YELLOW = '\033[1;33m'
        self.NC = '\033[0m'  # No Color

    def check_command(self, cmd: str, expected_version: str = None) -> bool:
        """Check if a command exists and optionally verify version."""
        self.total_checks += 1
        print(f"Checking {cmd}... ", end='', flush=True)

        try:
            result = subprocess.run(
                [cmd, '--version'],
                capture_output=True,
                text=True,
                timeout=5
            )

            if result.returncode == 0:
                version = result.stdout.split('\n')[0]
                print(f"{self.GREEN}✅{self.NC} {version}")
                self.passed_checks += 1
                return True
            else:
                raise FileNotFoundError

        except (FileNotFoundError, subprocess.TimeoutExpired):
            print(f"{self.RED}❌ NOT FOUND{self.NC}")
            self.failed_checks += 1
            return False

    def check_wsl2(self) -> bool:
        """Check if running in WSL2."""
        self.total_checks += 1
        print("Checking WSL2 kernel... ", end='', flush=True)

        try:
            with open('/proc/version', 'r') as f:
                version = f.read()

            if 'microsoft' in version.lower():
                kernel = version.split()[2]
                print(f"{self.GREEN}✅{self.NC} {kernel}")
                self.passed_checks += 1
                return True
            else:
                print(f"{self.YELLOW}⚠️{self.NC}  Not in WSL2 (native Linux?)")
                self.passed_checks += 1
                return True

        except FileNotFoundError:
            print(f"{self.YELLOW}⚠️{self.NC}  /proc/version not found")
            self.passed_checks += 1
            return True

    def check_git_config(self) -> bool:
        """Check Git user configuration."""
        self.total_checks += 1
        print("Checking Git configuration... ", end='', flush=True)

        try:
            name_result = subprocess.run(
                ['git', 'config', 'user.name'],
                capture_output=True,
                text=True,
                check=False
            )

            email_result = subprocess.run(
                ['git', 'config', 'user.email'],
                capture_output=True,
                text=True,
                check=False
            )

            name = name_result.stdout.strip()
            email = email_result.stdout.strip()

            if name and email:
                print(f"{self.GREEN}✅{self.NC} {name} <{email}>")
                self.passed_checks += 1
                return True
            else:
                print(f"{self.RED}❌ NOT CONFIGURED{self.NC}")
                print("  Run: git config --global user.name \"Your Name\"")
                print("  Run: git config --global user.email \"you@example.com\"")
                self.failed_checks += 1
                return False

        except Exception as e:
            print(f"{self.RED}❌ ERROR{self.NC}")
            self.failed_checks += 1
            return False

    def check_directory(self) -> bool:
        """Check if current directory is a Git repository."""
        self.total_checks += 1
        print("Checking project directory... ", end='', flush=True)

        git_dir = Path('.git')
        if git_dir.exists() and git_dir.is_dir():
            repo_path = Path.cwd()
            print(f"{self.GREEN}✅{self.NC} {repo_path} (Git repo)")
            self.passed_checks += 1
            return True
        else:
            print(f"{self.RED}❌ Not a Git repository{self.NC}")
            self.failed_checks += 1
            return False

    def run_all_checks(self) -> bool:
        """Run all environment checks."""
        print("=" * 40)
        print("  Environment Smoke Test")
        print("=" * 40)
        print()

        print("�️  System Information:")
        self.check_wsl2()
        print()

        print("�️  Development Tools:")
        self.check_command('python3')
        self.check_command('node')
        self.check_command('pnpm')
        self.check_command('git')
        print()

        print("� Configuration:")
        self.check_git_config()
        self.check_directory()
        print()

        print("=" * 40)
        print("  Results")
        print("=" * 40)
        print(f"Total checks: {self.total_checks}")
        print(f"{self.GREEN}Passed: {self.passed_checks}{self.NC}")

        if self.failed_checks > 0:
            print(f"{self.RED}Failed: {self.failed_checks}{self.NC}")
            print()
            print("❌ Environment check FAILED")
            return False
        else:
            print(f"{self.RED}Failed: 0{self.NC}")
            print()
            print("✅ Environment check PASSED")
            print("Your development environment is ready!")
            return True


def main():
    """Main entry point."""
    checker = EnvironmentChecker()
    success = checker.run_all_checks()
    sys.exit(0 if success else 1)


if __name__ == '__main__':
    main()
```

```python
def check_min_version(cmd: str, min_ver: str) -> bool:
    """Check if command meets minimum version requirement."""
    try:
        result = subprocess.run(
            [cmd, '--version'],
            capture_output=True,
            text=True,
            timeout=5
```
